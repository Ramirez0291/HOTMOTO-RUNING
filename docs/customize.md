# 業界の変え方

このリポジトリはいま「二輪市場」のサイトとして設定されています。別の業界（「法律」「HR」「金」など）に変えるときに書き換えるものは、ほぼすべて [`site/`](../site/)（このサイト自身の名前、文言、ブランド、ページ）と [`industry/`](../industry/)（業界の分類、情報源、プロンプト、しきい値）の 2 つのフォルダにあり、コードはほとんど変えません。

Claude Code や Codex のような Agent を使うなら、次の文をそのまま渡して、質問に答えてください：

```text
AGENTS.md と docs/customize.md を読んで、このサイトを「○○業界」のニュースサイトに変えてください。
気にしているのは：……（見張りたい情報源、重要だと思うニュース、重要でないもの。具体的なほどよい）。
終わったら npm run typecheck、npm test、node scripts/smoke.ts を実行し、まだ自分で決めるべきことを教えてください。
```

以下が、Agent（またはあなた）がやることです。順番に。

## 1. サイト名と文言：`site/site.ts`

- `name`：サイト名。ナビゲーション、タイトル、シェア画像、RSS、MCP、管理画面で使います。
- `subject`：業界名。画面の「二輪日報」「二輪ニュース」などがこれから作られます。
- `homeTitle`、`topicsTitle`、`description`、`tagline`、`keywords`：トップページとトピック一覧のタイトル、一言紹介、シェア画像の下の小さな文字、検索エンジン向けのキーワード。
- `locale`、`language`：表示言語（`ja-JP`）と、モデルが書く言語・翻訳の言語（`ja` か `zh`）。`language` を変えたら、`industry/prompts/` もその言語で書き直します（[アーキテクチャ](architecture.md) の「言語とタイムゾーン」）。
- `TIME_ZONE`：日付と時刻の基準（いまは日本時間）。日報の締め、画面の日付、定期作業がすべてこれを読みます。夏時間のない固定オフセットを書きます。
- `mcpPrefix`：MCP ツール名の接頭辞。`nirinhot` なら `nirinhot_get_latest` になります。誰かが接続した後は変えないでください。
- `interfaceVersion`：公開インターフェース（MCP、OpenAPI、`llms.txt`）のバージョン。上げるだけで下げません。既存の項目や意味を変えたらメジャーを上げます。
- `crawlerName`：情報源を取得するときに名乗る名前。他人のサイト名を使わないでください。
- `icp`：中国本土のサイトの届出番号（日本のサイトでは不要）。
- `github`：ソースコードのリポジトリのアドレス（任意）。入れるとサイドバーと「マイページ」の下に表示されます。
- `llmsIntro`：`llms.txt` の一言紹介の下の詳しい紹介（任意）。
- `rootIcons`：標準のアイコン以外にサイトのルートに置くアイコン。`site/brand/` のファイル名（任意）。
- `EDITION_TIMES`：日報・週報・月報の発行時刻（`TIME_ZONE` の時刻）。スケジュール、日報の収録の時間帯、欠号アラート、時刻に触れる文言がすべてこれを読みます。スケジュールは 30 分ごとに確認するので、正時か 30 分を書きます。
- `POLICY`：利用規約とプライバシーポリシーのページの名前と紹介。`terms.license` はどの用途に許諾が要るかを述べる文、`terms.headers` は公開インターフェースで利用規約を示すレスポンスヘッダー（どちらも任意）。`xPostIsFullText` は X の投稿そのものの文字を全文として扱うか（扱うなら、情報源が全文を許可したときだけ表示）。
- `ABOUT`：About ページの大見出し、4 つの工程の説明、運営者ブロック（任意）、著作権の説明、「利用規約」リンクのアンカー（`termsAnchor`、任意）。
- `CARDS`：各ページのシェア画像の文字。
- `ITEM_COPY`：モデルが書く一文の呼び名（`reasonLabel`、いまは「注目ポイント」）、読者がウェブとシェア画像で AI の採点を見られるか（`showScore`。表示だけの設定で、公開 API と MCP には点数が入ります）。
- `REPORTS`：日報・週報・月報の紙面の言い回し：題字の発行者の行と横の一語、各レポートページの説明、1 号の 1 本の呼び方（`entry`、いまは「件・トピック」）、題字のほかの数字の単位、シェア画像の件数の言い方。
- `ALERTS`、`SOURCE_DEFAULTS`、`COMMUNITY_FEEDS`：アラートのうちデプロイごとに変わる言い回し、管理画面で情報源を作るときに全文を出すかの既定、どのコミュニティサイトの情報源を投稿したアカウント単位で話題度に数えるか。
- `ACCESS`：Agent 向けの説明と `llms.txt` の、頻度の制限の言い方と推奨の User-Agent。前段のリバースプロキシで本当に IP ごとに制限しているときだけ `ratePerMinute` を書きます。
- `ADMIN`：管理画面の数か所の注意書き（任意）。
- `DEPLOYMENT`：このデプロイ自身の取り決め：認証情報のファイルの置き場所、本番の API の起動時に追加で確認する認証情報（`requiredSecrets`、既定は空）、CDN のオリジンのドメイン、管理画面のログイン後に戻るためのリクエストヘッダー、画像プロキシの転送量の上限、収集と画像で直接接続する（送信プロキシを通さない）ドメイン、厳選の評価に既定で使うサンプル。どれも書かなくてよい。
- `FEED_COPY`、`PUBLIC_CATEGORIES`：「すべてのニュース」RSS の説明に補う「含まないもの」、公開インターフェース（API、RSS、MCP）でウェブと異なるカテゴリ（例：あるカテゴリを別のカテゴリに統合する）。公開後は変えないでください。

サイトのアドレスはここには書かず、デプロイ時に環境変数 `SITE_URL` で設定します。

## 2. 分類、タグ、トピック：`industry/taxonomy.ts`、`industry/topics.json`

- `CATEGORIES`：トップページと「すべてのニュース」の絞り込みのカテゴリ。`key` は URL とインターフェースに出ます（`/all?category=`、`/feed/category/<key>.xml`）。公開後は変えないでください。`label` は表示名、`section` は日報・週報・月報の節（複数のカテゴリで 1 節を共有できる）、`guide` はこのカテゴリに何を入れるか・隣のカテゴリとの境目はどこかを書き、構造化のときにモデルに見せます（全体の分類原則は `prompts/structure.md`）。`commentary: true` は論評系（試乗記、論評）を示します：報じた出来事にこの種類の続報があると、当事者自身の発表でも日報では速報にだけ入れます（4 件以上の情報源が報じた場合を除く）。`feedLabel` はカテゴリ別 RSS のタイトルの名前（書かなければ `label`）。公開インターフェース・RSS・MCP で別のカテゴリに統合して出すなら（ウェブでは分けたまま）、`site.ts` の `PUBLIC_CATEGORIES` に書きます。
- `RELEASE`：この業界で最も注目される発表（二輪では新型車）。カテゴリとタグの両方が一致したものだけ数えます。日報の題字の「N 車種の新モデル」はこれで数えます（管理画面で分類を変えると、既刊の日報も数え直します）。`unit` は数字の後の言い方。そういう種類がない業界は `null` にすると、題字にこの数を出しません。
- `PLAIN_TERMS`：週報・月報の総括に、記事の中に出典がなくても書いてよい業界の一般語（小文字）。サイト名は自動で含まれます。総括が記事にない名前や数字を書いたら使いません（[厳選と校正](selection.md)）。
- `CATEGORY_TAGS`、`TOPIC_TAGS`、`ENTITY_TAGS`：モデルはタグをここからだけ選びます。最初のタグは必ず「分類タグ」です。`prompts/structure.md` と `prompts/content-understanding.md` にも業界のタグの規則（たとえば何が「新型車」か）が書いてあるので、業界を変えるときは一緒に変えます。
- `ENTITIES`：業界の主な企業や団体。「メーカー・企業」のトピックページに使います。`aliases` は構造化のモデルに見せ、`otherNames` は企業自身の別の呼び方（公式アカウント名、子ブランド）で、ニュースの主体を企業に結び付けるときや、タイトルがその企業を名指ししているかを判断するときにも使います。`IDENTITY_LEXICON`、`PUBLISHER_DOMAINS` は、原文にない企業をモデルがタイトルや要約に書き込むのを防ぐためのものです。その心配がない業界では空にしてかまいません。
- `ITEM_TYPES`：内容タイプ。採点プロンプトの重みの表と対応しているので、変えたらプロンプトも一緒に変えます。
- `topics.json`：トピック一覧（`/topics`）。サイトの起動時に読むので、変えたら再ビルド（`docker compose up -d --build`）で反映されます。3 つのグループに分かれます：`company`（企業と団体）、`field`（テーマ）、`genre`（コンテンツ形式）。`slug` は公開後は変えないでください。
  - `company` のトピックは `entityId`（`ENTITIES` の id）で、その企業を主体とする報道を集めます。報道の主体が複数の企業のときは、タイトルで名指ししたものだけ数えます。任意：`aliases`（検索欄でこの語だけを検索しても、その企業の報道が出る）。
  - `field` と `genre` のトピックは `tags` で、そのタグが付いた報道を集めます。

## 3. 情報源：`industry/sources.json`

初回起動時に取り込む示範の情報源です。既にあるものは上書きせず、以後の起動ではファイルにあってデータベースにないものだけを補います。ファイルから消してもデータベースからは消えません（要らないものは管理画面で停止します）。公開後によく使うのは管理画面の「情報源」ページで、新規作成、試しの取得、頻度の調整、停止、失敗の理由の確認ができます。

各情報源の主な項目：

| 項目 | 意味 |
|---|---|
| `kind` | `rss`、`web_list`（ウェブの一覧、セレクターを設定）、`json_list`（JSON のインターフェース）、`x_search`（X のアカウント、SocialData が必要）、`mp_account`（WeChat 公式アカウント、極致了が必要）、`external`（外部からの送信） |
| `config` | 情報源の種類ごとの設定。[情報源](sources.md) を参照 |
| `tier` | 情報源の格付け：`T1` 公式の一次情報、`T1_5` 公式アカウントと準公式、`T2` メディアと個人、`EXCLUDE_MP` 厳選に参加しない。格付けごとに入選のしきい値が違います。`T1` が「一次情報」で、別に印を付ける必要はありません |
| `owner_entity_id` | 任意。この情報源がどの企業のものか（`ENTITIES` の id）。同じ企業の複数の情報源は、話題度では 1 つの参加者として数えます。`T1_5` の公式アカウントを代表記事にするにもこれが必要です（[情報源](sources.md)） |
| `participation_mode` | `editorial` は厳選とすべてのニュースに入る、`hot_signal` は話題度の証拠にだけ使う、`isolated` はどの公開ページにも出さない |
| `site_fulltext` | サイト内で全文を表示できるか。**既定は無効**：要約と原文のリンクだけを表示します。情報源がはっきり許可しているときだけ有効にします |

いまの 18 の情報源は、メーカー公式（Honda 二輪、ヤマハ発動機、スズキ二輪、カワサキ）、欧州二輪車工業会（ACEM）、国内の二輪メディア（ヤングマシン、Webikeプラス、バイクのニュース、モーサイ、webオートバイ、BikeJIN、バージンハーレー）、海外メディア（MCN、Visordown、RideApart、RushLane の二輪、Electrek の電動バイク、Crash.net の MotoGP）です。全国軽自動車協会連合会や自工会の統計のように、一覧ではなくページを更新する形式の資料は、外部のスクリプトで `external` として送る方法があります（[情報源](sources.md)）。

## 4. 厳選の基準：`industry/prompts/`

最も時間をかける価値のある工程です。業界の知見はここに書きます。

| ファイル | 役割 |
|---|---|
| `prefilter.md` | 予備選別：この資料がこの業界の話か。広めに拾い、明らかに無関係なものだけを止める |
| `selection-score.md` | **採点基準**：0〜100 点。内容タイプ、5 つの軸、タイプごとの重み、普通に評価すべき価値、抑えるべきノイズ |
| `content-understanding.md` | 入選と入選に近い内容の書き方：日本語のタイトル、答えを先に書く要約、注目ポイント（タグも付けるが、ページのカテゴリとタグは `structure.md` から来る） |
| `rules-domain.md` | 業界用語の訳し方と残し方（いまは二輪の用語：bike はバイク、registrations は登録台数、型式は一字も変えない……） |
| `summarize-*.md` | それ以外の内容のタイトルと要約の書き方 |
| `structure.md` | カテゴリ、タグ、主体の企業、具体的な 1 つのニュースか複数をまとめた記事か、ニュースの事実の抽出（誰が、何を、何に対して、原文の出典と前提条件）。ページのカテゴリとタグ、トピックページ、出来事のまとめ、日報はすべてこれに頼る |
| `group-*.md` | 出来事のまとめ：2 本の報道が同じ出来事か、同じ出来事の続きか、別のことか。あわせて、厳選済みの内容に対して新しい情報があるかを判断し、なければ厳選に入れない |
| `story-digest.md` | 出来事のページのまとめ文 |
| `report-period.md`、`report-period-sections.md` | 週報・月報の総括と欄の導入（日報はルールで編み、プロンプトを使わない） |
| `translate-*.md` | 全文の翻訳 |

プロンプトでは `{{siteName}}` でサイト名を、`{{> ファイル名}}` で別のプロンプトを参照します。プロンプトを変えるのにコードは変えません。

**おすすめのやり方**：構造（5 つの軸の加重、ノイズを抑える規則、安全の境界）は残し、「何が重要か」「何がノイズか」の例だけを業界に合わせて替えます。いまの二輪の設定では、新型車・販売データ・規制・用品を重点に、中古車の相場・買取、レンタル・サブスク、販売店のキャンペーンをノイズとして抑えています。

## 5. しきい値と校正：`industry/selection.ts`

2 回の点数の合計が 2 × しきい値以上なら点数は足ります（足りたものも、まとめの段階の重複確認を通る必要があります。[厳選と校正](selection.md)）。既定のしきい値（T1 60、T1_5 65、T2 76）は AI 業界で校正されたもので、業界とプロンプトを替えたら校正し直す必要があります：

1. 自分の情報源から 100〜200 件の資料を選び、「選ぶ / 選ばない」を自分でラベル付けし、`.data/gold.jsonl` に保存します（形式は [厳選と校正](selection.md)、`industry/gold.example.jsonl` に 2 件の例があります）。
2. `node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl` を実行し、正解率、適合率、再現率と、しきい値ごとの結果を見ます。
3. 管理画面の SelectBench で判断を誤った資料を 1 件ずつ見て、採点プロンプトかしきい値を直し、もう一度実行します。

この工程で、サイトが「正しく選べるか」が決まります。

## 6. ブランド：`site/brand/`

- `logo.svg`、`icon.png`（512）、`icon-192.png`、`apple-icon.png`（180）、`favicon.ico`：サイトのアイコン。
- `Logo.tsx`：ウェブの左上のサイト名のロゴ。既定ではサイト名を文字で組みます。自分のロゴがあれば、`Wordmark` を自分の SVG に替えます（引数は同じに保つ）。
- `wordmark.svg`、`wordmark-dark.svg`（任意）：シェア画像とポスターの文字ロゴ。暗い版は暗いシェア画像に使います。なければサイト名の文字を使います。
- `nameplates/`：日報・週報・月報のページ上部の題字（「二輪日報」など）。業界名を変えたら作り直します：
  ```bash
  npm pack @fontsource/noto-sans-jp@5.3.0 && tar xzf fontsource-noto-sans-jp-5.3.0.tgz
  node scripts/nameplates.ts package
  ```
- About ページの QR コード：管理画面の「設定」でアップロードするか、画像を `site/brand/contact/` に置きます。

hotmoto の名前とロゴは使わないでください。

## 7. ページの文言：`site/pages/`、`site/public/`、`site/changelog.json`

- `pages/terms.md`、`pages/privacy.md`：利用規約とプライバシーポリシー。**いまはひな形です**。公開前に実際の状況に合わせて書き直し、必要に応じて専門家の確認を受けてください。表の「項目」「版」「施行日」、`ページ冒頭：` の引用、`フッター：` の行は、ページの部品として読み取られます。
- `public/`：サイトのルートにそのまま公開するファイル：`robots.txt`、`manifest.webmanifest`（スマートフォンのホーム画面に追加したときの名前とアイコン）、`openapi-v1.json`（公開 API の説明）、任意の `.well-known/security.txt`（セキュリティの問題の連絡先）。ファイル内の `{{siteName}}`、`{{siteUrl}}`、`{{description}}`、`{{tagline}}`、`{{locale}}`、`{{version}}`、`{{timeZone}}` はこのサイトの値に置き換わり、OpenAPI の `{{categories}}`、`{{categoryList}}` は公開のカテゴリに置き換わります。ないファイルへのアクセスは 404 です。
- `changelog.json`：更新履歴。新しい項目は先頭に書き、`latestVersion` をその日付と時刻にします。`kind` は「更新」「改善」「お知らせ」「提供終了」のいずれか。読者に必ず見てほしいものには `"urgent": true` を付けます（赤く「重要」と表示）。

## 8. モデルとデプロイ

- モデル：`.env` の `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。OpenAI 互換のインターフェースなら何でもよく、すべての工程が既定でこれを使います。`site/models.ts` には名前付きのモデル（それぞれ自分のアドレスと鍵の環境変数を使う）と、各工程で既定に使うモデルがあります。デプロイ時には環境変数（`.env.example` を参照）や管理画面の「モデル」ページで工程ごとに選び直せます。推論モデル（考えてから答える）を使うときは推論の枠を残します：既定のモデルは `LLM_REASONING_TOKENS`、名前付きのモデルは `site/models.ts` の `reasoningTokens`。残さないと推論が各工程の出力枠を使い切り、答えが空になって毎回失敗します。
- デプロイ：[デプロイ](deploy.md) を参照してください。

## 変えた後の確認

```bash
npm run typecheck
DATABASE_URL=postgres://…/nirinhot_test npm test     # データベース名は _test か _ci で終わる必要があり、アカウントにデータベースを作る権限が要る
node scripts/smoke.ts --base http://localhost:3000   # サイトが動いてから
```

プロンプトを書き直したりしきい値を校正し直したりしても、テストは失敗しません：テストは各工程で実際に描画されたプロンプトでリクエストを見分け、しきい値は `industry/selection.ts` から読みます。`tests/` には業界の分類、タグ、企業を使うテストがあり（いまは二輪の `new-models`、「新型車」、ホンダなど）、`industry/taxonomy.ts` を変えるとそれらのテストが失敗します。例をあなたの業界の対応するものに替えれば十分で、テストしている規則そのものは変える必要はありません。

それからサイトを開いて、トップページ、すべてのニュース、日報、トピックページ、About ページを見て、管理画面の「情報源」ページで情報源がすべて取得できているかを確認してください。
