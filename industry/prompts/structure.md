一、カテゴリ category（{{categoryCount}} つから 1 つ選ぶ）
いまの材料の主な情報で 1 つに分ける：文中に誰が出てくるかではなく、読者が主に得るのはどの変化、統計、規制、製品、評価、判断か。カテゴリとタグは同じ重点を表さなければならない。
{{categoryGuide}}
交差するときは本文の重心を見る：新型車の発表に試乗の感想が少し付いていても new-models、試乗記に価格の紹介が付いていても review、統計に解説が付いていても market。短い投稿は筆者の主投稿を優先し、引用の内容は文脈としてだけ使い、筆者自身の判断より優先しない。材料が足りないときは category を null にし、industry と推測しない。

二、タグ tags：1〜6 個の文字列を出力する。最初の 1 つは次の分類タグから必ず 1 つ選ぶ：{{categoryTags}}。その後に該当するタグを 0〜5 個付けてよく、次の 2 つのリストからだけ選ぶ：
- テーマ：{{topicTags}}
- 実体：{{entityTags}}
該当するテーマや実体がなければ分類タグだけを返し、数合わせのタグを付けない。「新型車」は新しい車種、新しいモデル、フルモデルチェンジで登場する車両、市販予定車とコンセプトモデルにだけ使う。既存車種の仕様変更・年式変更・カラー変更は「モデルチェンジ」、価格だけの変更は「価格改定」を使う。販売・登録・出荷・生産の統計は「販売・登録台数」、決算と業績予想は「決算・業績」、統計のない市場の分析は「市場動向」。リコール・改善対策は「リコール」、規制と制度は「規制・法改正」。用品とカスタムパーツの新製品は「用品・パーツ」。先に category を決め、最初のタグが同じ重点を表しているか確かめる。メーカー名やテーマで内容の形式を置き換えない。

三、主体 subjects：資料が実際に扱っている主体の企業（ついでに触れただけではない）。次の id を使う：{{entities}}。なければ空配列。

四、資料の範囲 scope：この資料自身からだけ判断し、候補の記事から逆算しない。
- single：中心の報道が 1 つの具体的な出来事だけ、またはその出来事についての 1 つの評価・分析・回答。同じシリーズで同時に発表された複数の排気量・グレード・仕様と、その装備・価格・発売計画は single に入る。具体的な出来事のない単一の論評や解説は single でよいが、fact は null。「同じ話題を論じている」ことで複数の出来事を single にまとめてはならない。
- composite：本文が、それぞれ独立した記事になりうる複数の出来事、製品発表、異なる人の発言を実質的に報じている。まず主体がそれぞれ何をしたかを数えてから scope を判断する：同じ企業、同じ日付、同じショー、同じ総合発表、同じ話題であっても、それらを 1 つの出来事にはできない。同じショーで複数のメーカーがそれぞれ新型車を発表したなら、複数の出来事である。共通点をまとめたショーの総評も composite で、「複数のメーカーが一緒に 1 回の発表をした」という fact を作ってはならない。ショーの振り返りと独立した製品の総覧も同じ。ほかの車種や人物を背景・比較・例として使うだけで、本文が 1 つの出来事か 1 つの評価に集中しているなら composite ではない。
- unknown：材料が足りず範囲を見分けられない。タイトルの語、長さ、fact を抽出できるかどうかだけで判断しない。

五、事実 fact：この資料がいま報じているその出来事を抽出し、同じ事実のまとめに使う：title（全角 30 字以内）、subject（動作をした主体）、action（今回の動作）、object（動作の具体的な対象）、occurredAt（原文が明示する今回の動作の日付 YYYY-MM-DD、不明なら null）。組織の製品やサービスの発表は、社員のアカウントが告知していてもその組織を subject にする。個人の講演や意見そのものは発言者を主体にし、所属先だからといって組織の発表とはしない。composite のときは必ず null。確かめられる出来事のない論評も null でよい。
まず今回の動作と背景を分ける：
- X の主投稿が試乗結果、比較結果、販売の数字、対応、販売開始などの新しい動作を加えているときは、fact は主投稿のその動作でなければならない。引用された古い発表投稿は、評価・対応される対象を説明するだけで、主投稿の事実の代わりにはならない。例：メディアの主投稿が新型車の比較テストの結果を公表し、メーカーの発表投稿を引用しているとき、主体はメディア、動作は比較テストの結果の公表、対象はその車種であり、メーカーが新型車を再び発表したのではない。
- 主投稿が引用投稿を転載・紹介するだけで、自分では別の動作をしていないときは、引用の中で伝えられている同じ出来事を抽出してよい。1 回の転載そのものを製品の新しい発表に作り変えてはならない。
- 新しく書かれた紹介、試乗記、振り返り、技術解説が既存の発表に触れているときは、今回の紹介・試乗・解説とその明確な追加内容を抽出し、本文が発表を振り返っているからといって「発表 / 発売 / 登場」と書いてはならない。例：「先週発表された新型車を、今日試乗した」は試乗である。先週は背景の発表にすぎず、今回の試乗の occurredAt にしてはならない。本文が、その車種や装備がいま初めて発売されると明示しているなら、今回の発売として抽出する。
- 発表日、取得日、引用投稿の日付を、今回の動作の日付として補ってはならない。「今日」はこの原文の発表日と合わせて解釈してよい。背景の日付しかない、または明確な日付がないときは null のままにする。
- 長く更新されているカタログ、諸元表、ラインアップの一覧、価格表のページが、既存の車種の発売日、価格、仕様を並べているだけなら、今回その車種を発表したことにはならない。原文が明示する新しい動作がなければ scope は unknown、fact は null。「ページに載っている」を「メーカーが新たに発表した」に書き換えてはならない。
fact が null でないときは evidence と conditions も含める：evidence は中心の事実を支える原文の一文だけを写す（600 文字以内、見つからなければ null）。conditions は結論の適用範囲を決める原文の短い文で最大 4 件、各件は {"quote":"原文の連続した一文（400 文字以内）"} だけ。この工程では条件を訳さず、まとめず、抜き出すだけである。
evidence は上で選んだ今回の動作を支えなければならない。主投稿に新しい動作があるときは主投稿から取り、引用の中の古い発表の文で今回の評価を証明しない。主投稿が引用投稿を純粋に転載しているときだけ、引用投稿の中心の証拠を使う。
全文（末尾の価格、対象範囲、販売の説明を含む）を読み通したうえで、条件の優先順位は次のとおり：1. 対象となる型式・年式・製造期間・車台番号の範囲・台数、と対象外の例外。両方あれば必ず両方残し、それぞれの対象を示す。2. 価格（税込・税抜）、発売日、販売地域、販売チャネル、受注期間、限定台数。3. 予約、予定、今後の導入などの制限。性能、評価、一般的な使い方の場面で条件の枠を使わない。明確な条件がないときだけ [] にし、予告を販売開始と書かない。
各 quote は原文の一文だけを担う。異なる位置の条件はそれぞれ別の項目にし、1 つの段落につなげてはならない。例：原文に "Deliveries start in March." と "Prices exclude VAT." があれば、[{"quote":"Deliveries start in March."},{"quote":"Prices exclude VAT."}] と出力し、"Deliveries start in March... Prices exclude VAT." と書いてはならない。原文の言語と文字を保ち、長すぎるときはより短い完全な文を選ぶ。訳したり書き換えたり途中を省いたり ... / … を自分で加えたりしない。つなぎ合わせた引用は捨てられる。quote は受け取った原文の本文や投稿の中で連続して見つかる文字でなければならず、タイトル、情報源のタグ、日本語訳から取ってはならない。

出力の前に今回の動作を確かめる（タイトルや宣伝の言い回しより優先する）：タイトルの Introducing、紹介、ついに登場といった言葉で、本文がはっきり示す前後関係を覆してはならない。本文が、以前にすでに発表され、いまその装備を紹介したり使い方を説明したりしていると言うなら、今回の action と fact.title は紹介・解説と書かなければならない。本文がその装備や車種が今回初めて発売・公開されると明示しているときだけ、発表・発売と書く。evidence は今回の紹介・解説の文から取り、背景の発表の文で新しい発表を証明しない。今回の紹介がいつ行われたかが明示されていなければ、occurredAt は必ず null とし、記事の発表日や以前の発表日で補わない。

JSON オブジェクトを 1 つだけ出力する。項目：category, tags, subjects, scope, fact。
